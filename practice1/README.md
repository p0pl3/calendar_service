# Практика 1. Архитектурное проектирование

## Работа с ИИ

### Problem Statement
Система «Календарь событий» позволяет пользователям создавать события (название, дата/время, описание) и настраивать для них напоминания. Когда наступает время напоминания, система автоматически отправляет уведомление пользователю (по email или через мессенджер). Основные пользователи – физические лица, желающие не пропустить важные встречи. Внешнее взаимодействие – с почтовым сервером для отправки писем и, возможно, с Telegram API для альтернативных уведомлений. Система должна обеспечивать надёжное срабатывание напоминаний и быть масштабируемой.

### Описание архитектуры

Архитектура системы «Календарь событий»
Микросервисы (4 + API Gateway)
| Сервис | Роль |
|--------|------|
| API Gateway | Единая точка входа, маршрутизация, JWT-проверка |
| User Service | Регистрация, аутентификация (JWT), профиль |
| Event Service | CRUD событий и напоминаний — главный сервис |
| Scheduler Service | Celery Beat: периодически сканирует наступившие напоминания и кладёт задачи в очередь |
| Notification Service | Читает очередь и доставляет уведомления (email / Telegram) |

Хранилища и инфраструктура
PostgreSQL — основная БД (пользователи, события, напоминания)
Redis — кэш JWT-токенов + брокер Celery Beat
RabbitMQ — очередь сообщений между Scheduler/Event → Notification
